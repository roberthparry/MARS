# TeX notation

`TeX_t`, declared in `TeX-t.h`, is an opaque, immutable mathematical notation
value. Use `TeX_builder_t` to construct one in reverse Polish order: enter
operands, then apply an operation. The builder owns every intermediate value;
there is no separate cleanup list. `TeX_builder_finish` transfers the single
completed formula to you. Free it with `TeX_free` and free the builder with
`TeX_builder_free`.

**RPN is the recommended way to author formulas.** Start with the
[quick start](#rpn-quick-start), then use the [operation reference](#reverse-polish-construction-contract)
and [HP48 stack controls](#hp48-style-stack-operations). The
[Maxwell example](#maxwells-equations-in-tensor-form) combines tensor indices,
covariant derivatives, equality and multiline alignment in one programme.

The builder supplies typesetting syntax without doing algebra. Optional
[input shortcuts](#optional-input-shortcuts) accept existing native mathematical
text or trusted TeX source. Mathematical objects already in memory keep their
ordinary output APIs, which handle rendering internally. No entry point runs a TeX engine.

Every push and operation returns a Boolean. A failure leaves the stack unchanged and
saves the first error. Later operations and finish fail until you explicitly
clear that error. This means the examples can check the finished result once,
without accidentally accepting an incomplete formula after an ignored failure.

Arithmetic follows ordinary RPN: push the left operand, push the right operand,
then apply one binary operator. For a further factor, push it and multiply again.
There is no operand-count argument for arithmetic. Functions consume argument
lists; the integer consumed when assembling a list is a stack control, not a printed number.

Operand entry implies a push: `TeX_symbol(builder, "x")` enters a symbol,
`TeX_integer(builder, 2)` enters an integer, and `TeX_pow(builder)` then
applies exponentiation to those two operands. The function names need neither
a `push_` nor an `apply_` prefix. The [construction contract](#reverse-polish-construction-contract)
classifies entry, application and stack-control functions by their effects.

`TeX_symbol` takes keyboard-friendly names such as `psi`, `mu`, `lambda`,
`Lambda`, `hbar`, `partial`, `nabla` and `infinity`; Unicode is optional. Arithmetic operations
supply their own syntax. `TeX_text` escapes literal prose. `TeX_raw`
accepts mathematical source written directly in TeX syntax or generated by another renderer. None retains
its input. `TeX_notation` copies an existing value,
including an operand already on the stack. `TeX_source` returns a borrowed
pointer, while `TeX_render` returns an independent `string_t`. Immutable values
may be read concurrently; access to a shared builder and destruction require
external synchronisation.

## RPN quick start

Each C block is a complete programme. The Markdown tests extract and compile
these exact blocks, run them and compare their output with the accompanying
text. Run them after the ordinary tests with
`MARS_ROOT="$PWD" make -j1 test-readme-examples`. A TeX-only run checks twenty-eight
programmes; other enabled examples are counted too.

Push the numerator first and the denominator second, then apply the fraction
and square root. Only the completed result and the builder require cleanup.

```c
/**
 * @file TeX_example_1.c
 * @brief Construct a fraction inside a square root in reverse Polish order.
 *
 * The builder owns every intermediate fragment and transfers the finished notation.
 */
#include <stdio.h>
#include <stdlib.h>

#include "TeX-t.h"

int main(void)
{
    TeX_builder_t *builder = TeX_builder_new();
    /* sqrt(x/2) */
    TeX_symbol(builder, "x");
    TeX_integer(builder, 2);
    TeX_frac(builder);
    TeX_sqrt(builder);
    TeX_t *formula = TeX_builder_finish(builder);
    TeX_builder_free(builder);
    int status = formula && puts(TeX_source(formula)) != EOF ? EXIT_SUCCESS : EXIT_FAILURE;
    TeX_free(formula);
    if (status != EXIT_SUCCESS)
        fputs("Could not construct or print TeX.\n", stderr);
    return status;
}
```

Output:

```text
\sqrt{\frac{x}{2}}
```

Rendered mathematics:

$$
\sqrt{\frac{x}{2}}
$$

## Reverse Polish construction contract

The reverse Polish interface implies entry or application through the function
name. `TeX_symbol`, `TeX_integer` and the other operand-entry functions add
values; `TeX_add`, `TeX_mul`, `TeX_frac` and `TeX_pow` apply operations to
existing values. Private fragment constructors remain implementation details.
An apply operation consumes its stated tail of the stack, in push order,
replacing it with one independently owned fragment. Stack
selection uses direct indexing. ROLL shifts only the selected pointer range;
ROT moves three pointers in constant time. Neither operation copies notation.

| Class | Functions | Stack effect, bottom to top |
| --- | --- | --- |
| Operand entry (push) | `TeX_symbol`, `TeX_integer`, `TeX_text`, `TeX_notation`, `TeX_space`; optional `TeX_math`, `TeX_expression`, `TeX_raw` | `S` → `S value`; no existing operand is consumed |
| Formula construction (apply) | Arithmetic, functions, scripts, tensors, calculus, relations, matrices and layouts in the reference below | Consumes the documented operands and replaces them with their notation |
| Stack manipulation and annotations | `TeX_dup`, `TeX_drop`, `TeX_swap`, `TeX_rot`, `TeX_roll`, `TeX_list`, `TeX_unlist`, `TeX_upper`, `TeX_lower`, `TeX_comma`, `TeX_semicolon` | Each has its documented stack effect; annotations replace the top value |
| Depth entry (push) | `TeX_depth` | `S` → `S depth`; existing operands remain intact |
| Inspection and lifetime | `TeX_builder_…`, `TeX_source`, `TeX_render`, `TeX_free` | Inspect, reset or release state as documented |
| Optional standalone conversion | `TeX_from_expression` | Converts a complete native mathematical string into owned notation |

In particular, `TeX_function(b, "sin")` applies a function to an argument list
already on the stack. `TeX_math(b, "sin(x)")` instead enters one formula from
native mathematical text. A name or presentation argument selects an operation;
it does not by itself make that function an operand-entry operation.

| Purpose | API and operand order, oldest first |
| --- | --- |

| Recovery | `TeX_builder_clear_error` retains operands; `TeX_builder_clear` discards operands and resets errors |

Pushes copy their inputs; the caller retains ownership of strings and existing
notation. The builder owns all pushed and intermediate values. A borrowed
`TeX_builder_peek` result must not be freed; it remains valid through further
pushes, but not after consumption, clearing or builder destruction.
`TeX_builder_finish` transfers ownership without copying. Free its result with
`TeX_free`; the builder is then empty and immediately reusable.

Lists are actual immutable objects, rather than text that is parsed again.
The HP48 sequence `a b 2 ->LIST` becomes pushes of `a`, `b`, and `2`, followed
by `TeX_list`. `TeX_unlist` reverses it, leaving `a b 2` on the stack.
The integer count is a stack control; it does not become part of the formula.
`TeX_depth` followed by `TeX_list` gathers all current operands. Nesting is
limited to 128 levels so copying and releasing authored structures remain bounded.
Matrix delimiter and derivative-style arguments select presentation; mathematical
counts, dimensions, labels and arguments come from stack operands.

All 24 Greek names are available in lowercase and with an initial capital for
uppercase letters, together with `varepsilon`, `vartheta`, `varkappa`, `varpi`,
`varrho`, `varsigma` and `varphi`. `hbar`, `partial`, `infinity` and `infty` select
common mathematical symbols. These use a compact perfect hash rather than a scan.
Other identifier names remain available. `TeX_function(b, "psi")` consumes a list and uses
the same ASCII naming; recognised standard functions retain their established
spelling, so `gamma` as a function denotes the gamma function while
`TeX_symbol(b, "gamma")` denotes the Greek letter. No special keyboard is needed.

Failures preserve the previous operands and save the first error:
`ERANGE` for stack underflow, `EINVAL` for invalid input or incomplete finish,
`EOVERFLOW` for dimensions that cannot fit and `ENOMEM` for allocation failure.
Later mutations and finish remain blocked until `TeX_builder_clear_error` or
`TeX_builder_clear` is called. Inspecting the stack remains possible after an
error. Invalid peek requests report `errno` without changing the saved error.
Because construction errors are saved, checking each completed formula covers
all its builder operations. The examples below also check printing and stop at
the first failure, using a shared cleanup path. Success is returned only after
every formula has printed.

Structured arithmetic retains operand precedence without parsing or simplifying
algebra. Sums and differences used as factors or power bases are visibly grouped;
subtraction preserves the scope of its right operand. Stack duplication and
`TeX_notation` retain this structure. Raw TeX source has
unknown structure and is conservatively grouped when used in arithmetic. Native
mathematical text continues to obtain its meaning from the expression, matrix,
equation and differential-equation modules through their internal callbacks.
TeX supplies presentation; it does not parse TeX back into mathematics.

## HP48-style stack operations

Levels count down from one at the top, as in the [HP48 user guide, chapter 3](https://www.hp.com/ctg/Manual/c00442262.pdf).
`TeX_dup` copies the top value. `TeX_rot` rotates the top three values;
it has the same effect as pushing `3` and calling `TeX_roll`.
`TeX_drop` removes the top value and releases its notation automatically. Borrowed
views of that value become invalid; all lower values and their views remain valid.
`TeX_swap` exchanges the top two values without allocating or copying notation,
preserving their identities, borrowed views and literal integer metadata.
ROLL consumes its level number, then moves that level of the remaining data
to the top. With the top at the right, `a b c 3 ROLL` becomes `b c a`.
SWAP has the same effect as pushing `2` then ROLL, without needing a control value.
Lower levels are untouched. DROP requires one operand and SWAP requires two;
underflow saves `ERANGE` and preserves the stack. A saved error blocks both
operations until explicitly cleared. Neither operation transfers ownership to the caller.

Push a ROLL control with `TeX_integer`; DUP and `TeX_notation`
preserve that literal integer. The supported level range is one through the
remaining stack depth. ROLL neither evaluates arithmetic notation nor parses
rendered TeX to obtain the level. An invalid control leaves the entire stack,
including the control, intact and saves an error for inspection or recovery.

This programme demonstrates DUP, DROP, SWAP, ROT and a four-level ROLL. Each row shows
the stack from bottom to top; inspecting it does not transfer ownership.

```c
/**
 * @file TeX_stack_example.c
 * @brief Demonstrate HP48-style stack manipulation without exposing notation ownership.
 *
 * Prints stack levels in push order after DUP, DROP, SWAP, ROT and a level-controlled ROLL.
 */
#include <stdio.h>
#include <stdlib.h>

#include "TeX-t.h"

static int show(const TeX_builder_t *builder)
{
    if (TeX_builder_error(builder))
        return -1;
    for (size_t level = TeX_builder_count(builder); level; --level) {
        const TeX_t *value = TeX_builder_peek(builder, level);
        if (!value || printf("%s%s", TeX_source(value), level == 1 ? "\n" : " ") < 0)
            return -1;
    }
    return 0;
}

int main(void)
{
    TeX_builder_t *builder = TeX_builder_new();
    int status = EXIT_FAILURE;
    if (!builder) goto done;
    TeX_integer(builder, 12);
    TeX_integer(builder, 34);
    TeX_dup(builder);
    if (show(builder)) goto done;

    TeX_drop(builder);
    if (show(builder)) goto done;

    TeX_swap(builder);
    if (show(builder)) goto done;

    TeX_builder_clear(builder);
    TeX_integer(builder, 12);
    TeX_integer(builder, 34);
    TeX_integer(builder, 56);
    TeX_rot(builder);
    if (show(builder)) goto done;

    TeX_builder_clear(builder);
    TeX_integer(builder, 555);
    TeX_integer(builder, 444);
    TeX_integer(builder, 333);
    TeX_integer(builder, 222);
    TeX_integer(builder, 4);
    TeX_roll(builder);
    if (show(builder)) goto done;
    status = EXIT_SUCCESS;
done:
    TeX_builder_free(builder);
    return status;
}
```

Output:

```text
12 34 34
12 34
34 12
34 56 12
444 333 222 555
```


## Indexed expression with nested roots

Leave the left side on the stack while constructing the right side. Push each
root's radicand before its index; push both fraction operands before applying
the fraction. The caption is escaped literal text, and the wide gap is selected
by name rather than by writing a TeX spacing command.

```c
/**
 * @file TeX_example_2.c
 * @brief Build an indexed equation, nested radicals and a literal caption using RPN.
 *
 * ASCII symbol names and structured arithmetic preserve authored order without TeX source fragments.
 */
#include <stdio.h>
#include <stdlib.h>

#include "TeX-t.h"

int main(void)
{
    TeX_builder_t *builder = TeX_builder_new();
    /* r_n = cbrt(1 + x_n^2)/sqrt(1 + lambda^2) */
    TeX_symbol(builder, "r");
    TeX_symbol(builder, "n");
    TeX_subscript(builder);

    /* cbrt(1 + x_n^2) */
    TeX_integer(builder, 1);
    TeX_symbol(builder, "x");
    TeX_symbol(builder, "n");
    TeX_integer(builder, 2);
    TeX_scripts(builder);
    TeX_add(builder);
    TeX_integer(builder, 3);
    TeX_root(builder);

    /* sqrt(1 + lambda^2) */
    TeX_integer(builder, 1);
    TeX_symbol(builder, "lambda");
    TeX_integer(builder, 2);
    TeX_pow(builder);
    TeX_add(builder);
    TeX_sqrt(builder);
    TeX_frac(builder);
    TeX_eq(builder);

    /* "scaled & normalised" */
    TeX_space(builder, TeX_SPACE_QUAD);
    string_t *caption = string_new_with("scaled & normalised");
    TeX_text(builder, caption);
    string_free(caption);
    TeX_integer(builder, 3);
    TeX_list(builder);
    TeX_sequence(builder);
    TeX_t *formula = TeX_builder_finish(builder);
    TeX_builder_free(builder);
    int status = formula && puts(TeX_source(formula)) != EOF ? EXIT_SUCCESS : EXIT_FAILURE;
    TeX_free(formula);
    if (status != EXIT_SUCCESS)
        fputs("Could not construct or print TeX.\n", stderr);
    return status;
}
```

Output:

```text
{r}_{n} = \frac{\sqrt[3]{1 + {x}_{n}^{2}}}{\sqrt{1 + {\lambda}^{2}}}\qquad \text{scaled \& normalised}
```

Rendered mathematics:

$$
{r}_{n} = \frac{\sqrt[3]{1 + {x}_{n}^{2}}}{\sqrt{1 + {\lambda}^{2}}}\qquad \text{scaled \& normalised}
$$

## A symmetric projection matrix

For real $x$, this projects onto the direction $(1,x)$. Each row is assembled
as a list, then both row lists become the matrix's input list.
The scalar and matrix are combined with thin
spacing by the binary `TeX_mul` operation.
`TeX_matrix` infers two rows and two columns from those lists. Square brackets
are the default. Push `6` and call `TeX_matrix_spacing` for six extra TeX points
between rows; the spacing is an operand, separate from the matrix's entries.

```c
/**
 * @file TeX_example_3.c
 * @brief Construct a scaled projection matrix from nested row-list operands.
 *
 * Dimensions come from list structure; no intermediate notation needs manual cleanup.
 */
#include <stdio.h>
#include <stdlib.h>

#include "TeX-t.h"

int main(void)
{
    /* P(x) = 1/(1 + x^2) * (1, x; x, x^2) */
    TeX_builder_t *builder = TeX_builder_new();
    TeX_symbol(builder, "x");
    TeX_integer(builder, 1);
    TeX_list(builder);
    TeX_function(builder, "P");
    TeX_integer(builder, 1);
    TeX_integer(builder, 1);
    TeX_symbol(builder, "x");
    TeX_integer(builder, 2);
    TeX_pow(builder);
    TeX_add(builder);
    TeX_frac(builder);

    TeX_integer(builder, 1);
    TeX_symbol(builder, "x");
    TeX_integer(builder, 2);
    TeX_list(builder);
    TeX_symbol(builder, "x");
    TeX_symbol(builder, "x");
    TeX_integer(builder, 2);
    TeX_pow(builder);
    TeX_integer(builder, 2);
    TeX_list(builder);
    TeX_integer(builder, 2);
    TeX_list(builder);
    TeX_matrix(builder);
    TeX_integer(builder, 6);
    TeX_matrix_spacing(builder);
    TeX_mul(builder);
    TeX_eq(builder);

    TeX_t *formula = TeX_builder_finish(builder);
    TeX_builder_free(builder);
    int status = formula && puts(TeX_source(formula)) != EOF ? EXIT_SUCCESS : EXIT_FAILURE;
    TeX_free(formula);
    if (status != EXIT_SUCCESS)
        fputs("Could not construct or print TeX.\n", stderr);
    return status;
}
```

Output:

```text
P\left(x\right) = \frac{1}{1 + {x}^{2}}\,\begin{bmatrix}1 & x \\[6pt] x & {x}^{2}\end{bmatrix}
```

Rendered mathematics:

$$
P\left(x\right) = \frac{1}{1 + {x}^{2}}\,\begin{bmatrix}1 & x \\[6pt] x & {x}^{2}\end{bmatrix}
$$

## Calculus and tensor notation

`TeX_sum`, `TeX_prod` and `TeX_integral` consume a bound list.
Push the body first; for an integral push the variable next. An empty list means
no bounds, one member is the lower bound, and two members are lower then upper.
Mark a lone upper bound with `TeX_upper` before assembling its list.
Repeated integral operations construct iterated integrals. `TeX_derivative`
consumes the body, variable and positive integer order; its argument selects
ordinary or partial presentation. Keep coefficients beside the
derivative's own fraction rather than placing it inside another fraction.

`TeX_tensor` consumes a base followed by a list of index labels. `TeX_upper`
marks an upper label; unmarked labels are lower, as are labels marked with
`TeX_lower`. Labels retain those marks through lists and stack manipulation.
The operation neither contracts indices nor checks dimensions.
There is no Cartesian restriction: the same layout handles arbitrary-rank
covariant, contravariant and mixed components in any coordinate basis. See the
[general tensor and connection example](#general-tensor-and-connection-notation)
for covariant derivatives, curvature and Christoffel symbols.
The [Maxwell example](#maxwells-equations-in-tensor-form) constructs the electromagnetic
field equations using ordered tensor indices and semicolon derivative marks.
`TeX_fence` supplies visible mathematical delimiters. These are notation
operations; the native mathematical modules own calculation and interpretation.

## Einstein, Schrödinger and Dirac equations

The following programme prints Einstein's field equations with explicit $c$,
the one-dimensional time-dependent Schrödinger equation, the free Dirac equation
in natural units, a wavefunction expansion and its normalisation. The Dirac
convention is Minkowski signature $(+,-,-,-)$, with repeated $\mu$ summed.
The equations follow David Tong's lectures on
[general relativity](https://www.damtp.cam.ac.uk/user/tong/gr/grhtml/S4.html),
[quantum mechanics](https://www.damtp.cam.ac.uk/user/tong/qm/qmhtml/S1.html) and
[the Dirac equation](https://www.damtp.cam.ac.uk/user/tong/qft/qfthtml/S4.html).

One reusable builder replaces the ownership list. A small helper constructs
psi(x,t); another prints and frees each finished formula.
Plain symbols and RPN operations supply every mathematical component, including
arithmetic and function calls. No TeX command fragments are needed. No extra tensor package
is needed; matrices use the standard `amsmath` environments.

```c
/**
 * @file TeX_physics.c
 * @brief Construct field equations and wavefunction notation from structured RPN operations.
 *
 * Symbols use ASCII names; arithmetic, calls and calculus supply their own presentation syntax.
 */
#include <stdio.h>
#include <stdlib.h>

#include "TeX-t.h"

static void wavefunction(TeX_builder_t *builder)
{
    /* psi(x,t) */
    TeX_symbol(builder, "x");
    TeX_symbol(builder, "t");
    TeX_integer(builder, 2);
    TeX_list(builder);
    TeX_function(builder, "psi");
}

static bool print_formula(TeX_builder_t *builder)
{
    TeX_t *formula = TeX_builder_finish(builder);
    bool ok = formula && puts(TeX_source(formula)) != EOF;
    TeX_free(formula);
    return ok;
}

int main(void)
{
    TeX_builder_t *b = TeX_builder_new();
    int status = EXIT_FAILURE;

    /* R_{mu nu} - R*g_{mu nu}/2 + Lambda*g_{mu nu} = (8*pi*G/c^4)*T_{mu nu} */
    TeX_symbol(b, "R");
    TeX_symbol(b, "mu");
    TeX_symbol(b, "nu");
    TeX_integer(b, 2);
    TeX_list(b);
    TeX_tensor(b);
    TeX_integer(b, 1);
    TeX_integer(b, 2);
    TeX_frac(b);
    TeX_symbol(b, "R");
    TeX_mul(b);
    TeX_symbol(b, "g");
    TeX_symbol(b, "mu");
    TeX_symbol(b, "nu");
    TeX_integer(b, 2);
    TeX_list(b);
    TeX_tensor(b);
    TeX_mul(b);
    TeX_sub(b);
    TeX_symbol(b, "Lambda");
    TeX_symbol(b, "g");
    TeX_symbol(b, "mu");
    TeX_symbol(b, "nu");
    TeX_integer(b, 2);
    TeX_list(b);
    TeX_tensor(b);
    TeX_mul(b);
    TeX_add(b);
    TeX_integer(b, 8);
    TeX_symbol(b, "pi");
    TeX_mul(b);
    TeX_symbol(b, "G");
    TeX_mul(b);
    TeX_symbol(b, "c");
    TeX_integer(b, 4);
    TeX_pow(b);
    TeX_frac(b);
    TeX_symbol(b, "T");
    TeX_symbol(b, "mu");
    TeX_symbol(b, "nu");
    TeX_integer(b, 2);
    TeX_list(b);
    TeX_tensor(b);
    TeX_mul(b);
    TeX_eq(b);
    if (!print_formula(b)) goto done;

    /* i*hbar*Dt(psi(x,t)) = -hbar^2/(2*m)*Dxx(psi(x,t)) + V(x,t)*psi(x,t) */
    TeX_symbol(b, "i");
    TeX_symbol(b, "hbar");
    TeX_mul(b);
    wavefunction(b);
    TeX_symbol(b, "t");
    TeX_integer(b, 1);
    TeX_derivative(b, TeX_DERIVATIVE_PARTIAL);
    TeX_mul(b);
    TeX_symbol(b, "hbar");
    TeX_integer(b, 2);
    TeX_pow(b);
    TeX_integer(b, 2);
    TeX_symbol(b, "m");
    TeX_mul(b);
    TeX_frac(b);
    wavefunction(b);
    TeX_symbol(b, "x");
    TeX_integer(b, 2);
    TeX_derivative(b, TeX_DERIVATIVE_PARTIAL);
    TeX_mul(b);
    TeX_neg(b);
    TeX_symbol(b, "x");
    TeX_symbol(b, "t");
    TeX_integer(b, 2);
    TeX_list(b);
    TeX_function(b, "V");
    wavefunction(b);
    TeX_mul(b);
    TeX_add(b);
    TeX_eq(b);
    if (!print_formula(b)) goto done;

    /* (i*gamma^mu*partial_mu - m)*psi = 0 */
    TeX_symbol(b, "i");
    TeX_symbol(b, "gamma");
    TeX_symbol(b, "mu");
    TeX_upper(b);
    TeX_integer(b, 1);
    TeX_list(b);
    TeX_tensor(b);
    TeX_mul(b);
    TeX_symbol(b, "partial");
    TeX_symbol(b, "mu");
    TeX_integer(b, 1);
    TeX_list(b);
```

## Existing renderers

The [expression](expression.md), [matrix](matrix.md), [equation](equation.md) and
[differential-equation](diffequation.md) output APIs retain their existing contracts.
TeX owns typesetting syntax, symbol spellings, grouping, delimiters and layout.
The mathematical modules supply owned semantic snapshots through callbacks; TeX
does not inspect their private objects or parse rendered output to recover meaning.
Expression selects operation semantics, binding values, constant identities,
series identities and temporary names. Matrix selects factors, additive constants
and native real/imaginary components. Equation and differential equation select
their solutions, conditions and derivation steps.

Rendering contexts and providers are private implementation details. Ordinary
callers continue to request `style_LATEX`, `MAT_STRING_LATEX` or the documented
`*_to_TeX_*` APIs; they never construct or manage a rendering context. The native
text convenience entry point delegates parsing to those same mathematical modules.

Wrapped and unwrapped expressions share one semantic renderer. TeX requests
native-selected additive terms only when the ordinary body exceeds its line
budget. For wide complex matrices, it requests native numeric components and
arranges them as real and imaginary matrices. Neither operation reparses numeric
or TeX strings. Each traversal has independent memoisation and cycle detection;
shared children render once. Native formatting and temporary-name scopes remain
thread-local. Recognised numeric constants use retained constant IDs directly,
with a perfect-hash candidate lookup and full-precision equality for untagged
values. Parsing, evaluation and solving remain native mathematical operations.

`TeX_bound` composes a braced body with optional bindings, `TeX_scaled`
places a scalar factor beside a body, and `TeX_cartesian_sum` aligns real
and imaginary components. `TeX_symmetric_pair` composes a common centre plus or minus an offset,
with optional offset grouping and a common denominator. These are RPN operations:
they consume stack operands, leave their result owned by the builder and return
success or failure. Only `TeX_builder_finish` transfers that result to the caller.

## RPN counterparts to native calculus

Each original expression labels its corresponding block below. The programme builds
every formula from the string-conversion list using stack operations, then prints and
releases each completed result.
The same builder is reused after `TeX_builder_finish` empties its stack.

`TeX_transform` consumes the body, source variable and target variable. `TeX_prod`
uses the same bounds convention as `TeX_sum`; construct an annotation such as `k = 1`
with `TeX_eq` before applying the product or sum.

`TeX_partial` consumes the body followed by the coordinate variables in application
order. Repeating a variable gives a higher derivative; different variables give mixed
derivatives. The displayed denominator reverses that order to show operator composition.
The Bessel and Lambert functions use a subscripted function name followed by `TeX_apply`.

The resulting operators match the native-text example, with the explicit grouping and
spacing supplied by the builder. These operations construct notation without evaluating it.

## Inequalities and approximate relations

Push the left operand, push the right operand, then apply the relation. These
operations replace both operands with one result and can be repeated to extend
an ordered chain. They construct notation without comparing values or choosing
a numerical tolerance.

| Keyboard text | RPN operation | Rendered relation |
|---|---|---|
| `<` | `TeX_lt` | $<$ |
| `<=` | `TeX_le` | $\le$ |
| `>=` | `TeX_ge` | $\ge$ |
| `>` | `TeX_gt` | $>$ |
| `!=` | `TeX_ne` | $\ne$ |
| `==` | `TeX_eq` | $=$ |
| `~~=` | `TeX_approx` | $\approx$ |
| `~==` | `TeX_cong` | $\cong$ |

A single `=` remains an equality alias. Text input also accepts `≤`, `≥`, `≠`,
`≈` and `≅`. The equation module recognises complete top-level relation tokens;
the mathematical modules parse each operand, and TeX owns the displayed symbols.
Relations inside function arguments or parenthesised scalar operands are not
part of this input grammar. Bindings retain their ordinary meaning and do not
replace the symbolic operands with numerical values.

Both `TeX_from_expression` and `TeX_math` accept this text. In Markdown,
put the approximate spellings in backticks: paired `~~` otherwise marks text
as struck through. No backslash belongs in the mathematical input.

This complete programme constructs each relation independently through RPN and
text, checks that the outputs agree, and prints the result. It finishes with a
mixed strict/inclusive chain.

```c
/**
 * @file TeX_relations_example.c
 * @brief Construct inequalities, equalities and approximate relations with RPN and keyboard text.
 *
 * Each relation is constructed independently through both interfaces and printed
 * after checking that they agree. One builder owns all intermediate notation.
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#include "TeX-t.h"

static int print_match(TeX_builder_t *builder, const char *source)
{
    TeX_t *rpn = TeX_builder_finish(builder);
    string_t *input = string_new_with(source);
    TeX_t *text = input ? TeX_from_expression(input) : NULL;
    int status = rpn && text && !strcmp(TeX_source(rpn), TeX_source(text)) &&
                 printf("%s -> %s\n", source, TeX_source(rpn)) >= 0 ? EXIT_SUCCESS : EXIT_FAILURE;
    TeX_free(text);
    string_free(input);
    TeX_free(rpn);
    return status;
}

int main(void)
{
    const struct {
        const char *source;
        bool (*operation)(TeX_builder_t *);
    } relations[] = {
        {"x < y", TeX_lt},
        {"x <= y", TeX_le},
        {"x >= y", TeX_ge},
        {"x > y", TeX_gt},
        {"x != y", TeX_ne},
        {"x == y", TeX_eq},
        {"x ~~= y", TeX_approx},
        {"x ~== y", TeX_cong}
    };
    TeX_builder_t *b = TeX_builder_new();
    int status = EXIT_SUCCESS;
    for (size_t i = 0; i < sizeof relations / sizeof *relations; ++i) {
        TeX_symbol(b, "x");
        TeX_symbol(b, "y");
        relations[i].operation(b);
        if (print_match(b, relations[i].source)) {
            status = EXIT_FAILURE;
            break;
        }
    }
    if (status == EXIT_SUCCESS) {
        /* 0 < x <= 1 */
        TeX_integer(b, 0);
        TeX_symbol(b, "x");
        TeX_lt(b);
        TeX_integer(b, 1);
        TeX_le(b);
        status = print_match(b, "0 < x <= 1");
    }
    TeX_builder_free(b);
    if (status != EXIT_SUCCESS)
        fputs("Could not construct matching relation notation.\n", stderr);
    return status;
}
```

## Prime notation with RPN

Push the body, push its integer order, then call `TeX_prime(builder)` to construct a derivative marked
by primes. Orders one, two and three produce single, double and triple primes;
larger orders use a parenthesised superscript, such as $y^{(4)}$. Zero is rejected
without consuming the operand. Compound operands are grouped before the prime
is attached. The operation constructs notation without differentiating.
It also primes index labels, as shown in the
[coordinate-transformation example](#primed-indices-and-coordinate-transformations).

Use `TeX_apply` after a prime to show a point condition: the function and its
argument list are separate stack operands. This complete programme constructs the
same equation and initial conditions as the
[primed native-text example](#bound-matrix-powers-and-differential-equation-problems).
`TeX_depth` and `TeX_list` collect the three equalities and two intervening spaces;
`TeX_sequence` joins that list. The builder owns every intermediate value.

```c
/**
 * @file TeX_primes_rpn_example.c
 * @brief Construct a primed ordinary differential equation and its point conditions using RPN operations.
 *
 * Primes mark derivative order without differentiating. Function application
 * supplies the evaluation point; ordinary stack arithmetic builds the equation.
 */
#include <stdio.h>
#include <stdlib.h>

#include "TeX-t.h"

int main(void)
{
    TeX_builder_t *b = TeX_builder_new();

    /* y'' + 3y' + 40y = 0 */
    TeX_symbol(b, "y");
    TeX_integer(b, 2);
    TeX_prime(b);
    TeX_integer(b, 3);
    TeX_symbol(b, "y");
    TeX_integer(b, 1);
    TeX_prime(b);
    TeX_mul(b);
    TeX_add(b);
    TeX_integer(b, 40);
    TeX_symbol(b, "y");
    TeX_mul(b);
    TeX_add(b);
    TeX_integer(b, 0);
    TeX_eq(b);

    TeX_space(b, TeX_SPACE_QUAD);

    /* y'(0) = 1 */
    TeX_symbol(b, "y");
    TeX_integer(b, 1);
    TeX_prime(b);
    TeX_integer(b, 0);
    TeX_integer(b, 1);
    TeX_list(b);
    TeX_apply(b);
    TeX_integer(b, 1);
    TeX_eq(b);

    TeX_space(b, TeX_SPACE_QUAD);

    /* y(0) = 0 */
    TeX_symbol(b, "y");
    TeX_integer(b, 0);
    TeX_integer(b, 1);
    TeX_list(b);
    TeX_apply(b);
    TeX_integer(b, 0);
    TeX_eq(b);

    TeX_depth(b);

    TeX_list(b);

    TeX_sequence(b);
    TeX_t *notation = TeX_builder_finish(b);
    int printed = notation ? puts(TeX_source(notation)) : EOF;
    TeX_free(notation);
    TeX_builder_free(b);
    if (printed == EOF) {
        fputs("Could not construct primed derivative notation.\n", stderr);
        return EXIT_FAILURE;
    }
    return EXIT_SUCCESS;
}
```

## General tensor and connection notation

`TeX_tensor` consumes a base and one ordered index list. Mark an upper label
with `TeX_upper` before adding it to the list; unmarked labels are lower.
There are no C arrays of labels or positions. Lists can be duplicated,
reordered and expanded with `TeX_unlist`, just like other stack operands. It supports
arbitrary tensor rank in any coordinate basis, including covariant, contravariant
and mixed components. It imposes no metric, signature or dimension. Index labels
can themselves be constructed notation, including the primed label in the final
example below. Repeated labels remain visible; no contraction is evaluated.
Adjacent indices of the same variance share one script, as in $F_{\mu\nu}$.
Changes between upper and lower indices retain their ordered horizontal slots.
Apply `TeX_prime` to an index label before `TeX_upper` or `TeX_lower` and list assembly.
The [coordinate-transformation example](#primed-indices-and-coordinate-transformations) uses this for
both upper and lower primed indices and the corresponding Jacobian factors.
Comma and semicolon marks provide [component derivative notation](#comma-and-semicolon-derivative-indices),
including forms such as $V^\nu{}_{,\mu}$ and $V_{i;j}$.

The same index layout also applies to indexed operators and connection
coefficients. Push `nabla` or `partial`, attach a lower direction index with
`TeX_tensor`, then combine it with its operand using `TeX_mul`.

The programme shows first- and second-kind Christoffel symbols for a Levi–Civita
connection, followed by the vector and covector component identities. A comma
marks partial differentiation and a semicolon marks covariant differentiation:
$V^\nu{}_{,\mu}=\partial V^\nu/\partial x^\mu$ and $V^\nu{}_{;\mu}$ is the
corresponding covariant derivative. The repeated index $\lambda$ is summed in
each identity; $\mu$ and $\nu$ are free indices.
Christoffel symbols are connection coefficients; they do not transform as tensors
under general coordinate changes.
The signs and index conventions follow
[David Tong's discussion of connections](https://www.damtp.cam.ac.uk/user/tong/gr/grhtml/S3.html).

This is presentation support. It preserves the supplied formulas without
computing a connection, transforming components, inferring symmetries or carrying
out tensor calculus. Tensor algebra and native-text tensor grammar remain deferred;
the [tensor design](design-notes/tensors.md) records their proposed native module,
MTW conventions and Lab mode. That module will supply mathematical semantics to
the existing notation interface; the TeX builder remains a typesetting API.
Raw TeX remains available for further specialised notation.

## Newlines, indentation and alignment

TeX_newline combines two stack rows; repeating it extends the same block.
TeX_align aligns the stored relation signs in that block, including equalities,
inequalities and approximate relations. It also accepts a list of rows.
TeX_indent consumes a body followed by an integer spacing in TeX points.
Apply it to a continuation row or to a complete block.

Relations constructed by RPN retain their sides and operators, so alignment does
not search the generated TeX for an equals sign. Native-text and raw-TeX rows
remain whole cells. For explicit column boundaries, supply nested row lists;
the second formula demonstrates this without raw syntax or C arrays. These cells
use a left-aligned array with space between columns. Relation rows use an aligned
environment with their operators on a shared vertical line.

The first block shows three independent relations and an indented expression on
four rows. Render multiline notation in a display-math block (`$$` delimiters in
Markdown) so its row and column layout is presented as a complete display.

## Comma and semicolon derivative indices

TeX_comma marks an index label as a partial-derivative direction, and
TeX_semicolon marks a covariant-derivative direction. Apply either operation

a C-side count or index array. The tensor's own indices precede its derivative
indices in that list.

Adjacent derivative labels of the same placement share a script: an upper
component followed by a lower comma index gives $V^\nu{}_{,\mu}$, whilst a lower
component followed by a lower semicolon index gives $V_{i;j}$.

between upper and lower placement retain ordered slots. An explicit upper or
lower mark selects placement without raising or lowering an index with a metric.

A marked list supplies several derivative directions. Their order is preserved,
including when comma and semicolon groups are mixed; covariant derivatives are
never commuted. This constructs notation only: it does not differentiate a
field, choose a connection or calculate Christoffel symbols. Native-text tensor
grammar and tensor algebra remain deferred.

## Primed indices and coordinate transformations

These three conventions express the same transformation of a mixed tensor's
components. Bars identify the transformed variables and components in the legacy
form; primes identify the transformed chart through the indices in the other two.

| Convention | Coordinate-transformation law |
| --- | --- |
| Barred variables | $\overline{T}^{\mu}{}_{\nu}=\dfrac{\partial\overline{x}^{\mu}}{\partial x^{\alpha}}\dfrac{\partial x^{\beta}}{\partial\overline{x}^{\nu}}T^{\alpha}{}_{\beta}$ |
| Primed Greek indices | $T^{\mu'}{}_{\nu'}=\dfrac{\partial x^{\mu'}}{\partial x^{\alpha}}\dfrac{\partial x^{\beta}}{\partial x^{\nu'}}T^{\alpha}{}_{\beta}$ |
| Primed Latin indices | $T^{a'}{}_{b'}=\dfrac{\partial x^{a'}}{\partial x^{c}}\dfrac{\partial x^{d}}{\partial x^{b'}}T^{c}{}_{d}$ |

Each convention has a complete RPN programme below. No TeX source fragments are needed.

### Primed Greek indices

Prime the **index label**, then select its placement and assemble the index list.
For example, `TeX_symbol(b, "mu")`, `TeX_integer(b, 1)`, `TeX_prime(b)` and
`TeX_upper(b)` supply an upper $\mu'$ index. The same sequence with `TeX_lower`
supplies a lower $\mu'$ index. Priming the completed tensor would instead put the
prime on the whole expression.

Here primes distinguish coordinates $x^{\mu'}$ from coordinates $x^\alpha$;
they do not denote differentiation. Under a smooth, invertible change of
coordinates, each upper index contributes a forward Jacobian and each lower
index an inverse Jacobian. This example writes the transformation law for a
mixed tensor of type $(1,1)$:

$$
T^{\mu'}{}_{\nu'} =
\frac{\partial x^{\mu'}}{\partial x^\alpha}
\frac{\partial x^\beta}{\partial x^{\nu'}}
T^\alpha{}_{\beta}.
$$

Repeated unprimed indices $\alpha$ and $\beta$ are summed. The primed indices
$\mu'$ and $\nu'$ are free on both sides. No Cartesian coordinates, orthogonal
change of basis or metric are assumed. The builder typesets the law supplied by
the caller; it does not compute the Jacobians or transform component values.

### Latin-index equivalent

Using lowercase Latin labels $a,b,c,d,e,\ldots$ and their primed counterparts
$a',b',c',d',e',\ldots$, the same component law is

$$
T^{a'}{}_{b'} =
\frac{\partial x^{a'}}{\partial x^{c}}
\frac{\partial x^{d}}{\partial x^{b'}}
T^{c}{}_{d}.
$$

Here $a'$ and $b'$ are free, whilst $c$ and $d$ are summed over the coordinate
dimension. The Latin labels cover the whole coordinate range; they do not
restrict the tensor to spatial or Cartesian components. As above, primes mark
the new chart and do not denote derivatives. These are coordinate-component
indices, rather than an additional operation on the tensor.

Only the symbol names differ from the Greek-index programme. `TeX_prime` still
acts on each index label before `TeX_upper`, `TeX_lower` and `TeX_tensor`.

## Maxwell's equations in tensor form

In SI units, Maxwell's equations with electric sources can be written as

$$
\begin{aligned}
F^{\mu\nu}{}_{;\mu} &= \mu_0 J^\nu, \\
F_{\mu\nu;\lambda}+F_{\nu\lambda;\mu}+F_{\lambda\mu;\nu} &= 0.
\end{aligned}
$$

Here $F_{\mu\nu}=-F_{\nu\mu}$ is the electromagnetic field tensor and $J^\nu$
is the four-current. Use signature $(+,-,-,-)$ and $x^0=ct$; in Cartesian
coordinates $J^\nu=(c\rho,j_x,j_y,j_z)$ and
$F_{\mu\nu}=A_{\nu,\mu}-A_{\mu,\nu}$ for the four-potential $A_\mu$.
$\mu_0$ is the vacuum permeability. Greek indices run from zero to three.

Semicolons denote covariant differentiation with the Levi–Civita connection.
The first equation contracts $\mu$, leaving $\nu$ free. In the second, all three
indices are free and the terms follow a cyclic permutation. In flat spacetime
with Cartesian coordinates, semicolons become commas. The equations then combine
Gauss's and Ampère–Maxwell's laws in the first line, and Faraday's law and the
absence of magnetic charge in the second. See the
[SI tensor formulation](https://www.damtp.cam.ac.uk/user/tong/em/el4.pdf#page=19)
and its [covariant extension](https://www.damtp.cam.ac.uk/user/tong/gr/grhtml/S3.html).

The programme constructs both equations and aligns their equality signs. Each
statement occupies its own line; the comments identify the formula being built.

```c

 *

 * The builder owns every intermediate value and transfers the completed two-row display.
 */
#include <stdio.h>
#include <stdlib.h>

#include "TeX-t.h"

int main(void)
{
    TeX_builder_t *b = TeX_builder_new();
    int status = EXIT_FAILURE;
    if (!b) goto done;

    /* F^{mu nu}_{;mu} = mu_0 J^nu */
    TeX_symbol(b, "F");
    TeX_symbol(b, "mu");
    TeX_upper(b);
    TeX_symbol(b, "nu");
    TeX_upper(b);
    TeX_symbol(b, "mu");
    TeX_semicolon(b);
    TeX_integer(b, 3);
    TeX_list(b);
    TeX_tensor(b);
    TeX_symbol(b, "mu");
    TeX_integer(b, 0);
    TeX_subscript(b);
    TeX_symbol(b, "J");
    TeX_symbol(b, "nu");
    TeX_upper(b);
    TeX_integer(b, 1);
    TeX_list(b);
    TeX_tensor(b);
    TeX_mul(b);
    TeX_eq(b);

    /* F_{mu nu;lambda} + F_{nu lambda;mu} + F_{lambda mu;nu} = 0 */
    TeX_symbol(b, "F");
    TeX_symbol(b, "mu");
    TeX_symbol(b, "nu");
    TeX_symbol(b, "lambda");
    TeX_semicolon(b);
    TeX_integer(b, 3);
    TeX_list(b);
    TeX_tensor(b);
    TeX_symbol(b, "F");
    TeX_symbol(b, "nu");
    TeX_symbol(b, "lambda");
    TeX_symbol(b, "mu");
    TeX_semicolon(b);
    TeX_integer(b, 3);
    TeX_list(b);
    TeX_tensor(b);
    TeX_add(b);
    TeX_symbol(b, "F");
    TeX_symbol(b, "lambda");
    TeX_symbol(b, "mu");
    TeX_symbol(b, "nu");
    TeX_semicolon(b);
    TeX_integer(b, 3);
    TeX_list(b);
    TeX_tensor(b);
    TeX_add(b);
    TeX_integer(b, 0);
    TeX_eq(b);

    TeX_newline(b);
    TeX_align(b);
    TeX_t *notation = TeX_builder_finish(b);
    if (notation && puts(TeX_source(notation)) != EOF)

    TeX_free(notation);
```

## Quantum operators, states and adjoints

`TeX_hat` covers the complete top operand with a hat. Apply it before
`TeX_pow` to show the square of a hatted operator; applying it afterwards
puts the hat over the entire power. `TeX_dagger` marks an adjoint and groups
compound operands. For a matrix the adjoint is its complex conjugate transpose;
a scalar complex conjugate is a different operation.

State operations consume labels: `TeX_bra` and `TeX_ket` consume one,
`TeX_braket` consumes left and right labels, and `TeX_ketbra` consumes ket
and bra labels. `TeX_matrix_element` consumes left label, operator and right
label, in that order. The delimiters scale with their contents. Angle fences
also express an expectation value.

This programme constructs a Hamiltonian, an expectation value, an inner
product, an outer product, an operator adjoint and the ket–bra adjoint identity.
The expectation-value identity assumes a normalised state. These are
presentation operations: they do not evaluate, normalise or rearrange operators.

```c
/**
 * @file TeX_quantum_rpn_example.c
 * @brief Construct quantum operators, state products and adjoints with the RPN interface.
 *
 * Every operand is owned by the builder. This example constructs notation, without evaluating operators
 * or state products. The expectation-value identity assumes a normalised state.
 */
#include <stdbool.h>
#include <stdio.h>
#include <stdlib.h>

#include "TeX-t.h"

static bool print_formula(TeX_builder_t *b)
{
    TeX_t *formula = TeX_builder_finish(b);
    bool ok = formula && puts(TeX_source(formula)) != EOF;
    TeX_free(formula);
    return ok;
}

int main(void)
{
    TeX_builder_t *b = TeX_builder_new();
    int status = EXIT_FAILURE;

    /* H_op = p_op^2/(2*m) + V(x,t) */
    TeX_symbol(b, "H");
    TeX_hat(b);
    TeX_symbol(b, "p");
    TeX_hat(b);
    TeX_integer(b, 2);
    TeX_pow(b);
    TeX_integer(b, 2);
    TeX_symbol(b, "m");
    TeX_mul(b);
    TeX_frac(b);
    TeX_symbol(b, "x");
    TeX_symbol(b, "t");
    TeX_integer(b, 2);
    TeX_list(b);
    TeX_function(b, "V");
    TeX_add(b);
    TeX_eq(b);
    if (!print_formula(b)) goto done;

    /* <p> = <psi|p_op|psi> */
    TeX_symbol(b, "p");
    TeX_fence(b, TeX_FENCE_ANGLE);
    TeX_symbol(b, "psi");
    TeX_symbol(b, "p");
    TeX_hat(b);
    TeX_symbol(b, "psi");
    TeX_matrix_element(b);
    TeX_eq(b);
    if (!print_formula(b)) goto done;

    /* <phi|psi> */
    TeX_symbol(b, "phi");
    TeX_symbol(b, "psi");
    TeX_braket(b);
    if (!print_formula(b)) goto done;

    /* |psi><phi| */
    TeX_symbol(b, "psi");
    TeX_symbol(b, "phi");
    TeX_ketbra(b);
    if (!print_formula(b)) goto done;

    /* (A_op)^dagger */
    TeX_symbol(b, "A");

    TeX_dagger(b);
    TeX_symbol(b, "psi");
    TeX_bra(b);
    TeX_eq(b);
    if (!print_formula(b)) goto done;

    status = EXIT_SUCCESS;

    TeX_builder_free(b);
    if (status != EXIT_SUCCESS)

}
```

### ASCII text equivalents

The same notation can be entered using `hat(H)` or the suffix `H_op`,
`dagger(A)`, `bra(@psi)`, `ket(@psi)`, `braket(@phi,@psi)`,
`ketbra(@psi,@phi)`, `matrix_element(@psi,p_op,@psi)` and `expect(p)`.
All these spellings use a normal keyboard. Native mathematical text uses
`@psi`; RPN symbol entry uses `"psi"`.

Explicit operator input preserves its arithmetic order without ordinary scalar
simplification. For example, `B_op*A_op` stays B followed by A. Named calls
are used instead of literal angle/bar input, which would conflict with
inequalities and binding separators. This adds notation support to
`TeX_from_expression`; it does not add quantum algebra to expression evaluation.

```c
/**
 * @file TeX_quantum_text_example.c
 * @brief Convert ASCII operator and Dirac notation into mathematical TeX.
 *
 * The native presentation reader retains explicit operator order without evaluating quantum expressions.
 * Returned notation owns its output independently of the temporary input string.
 */
#include <stdio.h>
#include <stdlib.h>

#include "TeX-t.h"

int main(void)
{
    const char *const sources[] = {
        "H_op=p_op^2/(2*m)+V(x,t)",
        "expect(p)=matrix_element(@psi,p_op,@psi)",
        "braket(@phi,@psi)",
        "ketbra(@psi,@phi)",
        "dagger(hat(A))",
        "dagger(ket(@psi))=bra(@psi)"
    };
    for (size_t i = 0u; i < sizeof sources / sizeof *sources; ++i) {
        string_t *input = string_new_with(sources[i]);
        TeX_t *notation = input ? TeX_from_expression(input) : NULL;
        string_free(input);
        int printed = notation ? puts(TeX_source(notation)) : EOF;
        TeX_free(notation);
        if (printed == EOF) {
            fputs("Could not convert quantum notation.\n", stderr);
            return EXIT_FAILURE;
        }
    }
    return EXIT_SUCCESS;
}
```

## Optional input shortcuts

Use the RPN builder for new formulas. These shortcuts are useful when the input
already exists in another form; they use the same TeX presentation module.

| Input already available | Recommended entry point |
| --- | --- |
| Native mathematical text in a C string | `TeX_math` adds one operand to the builder |
| Native mathematical text in a `string_t` | `TeX_expression` adds one operand to the builder |
| Complete native mathematical text requiring no further composition | `TeX_from_expression` returns one owned value |
| Trusted TeX source | `TeX_raw` adds one operand without parsing or escaping it |
| An expression, equation, matrix or differential equation object | Request that module's TeX output style |

`TeX_eq` is the public equality operation. Build multiline equations using
`TeX_newline` and `TeX_align`. Fragment-by-fragment constructors and specialised
native-renderer layouts are private implementation details; applications do
not need intermediate ownership lists, layout styles or rendering contexts.

## Ordinary mathematical text without TeX commands

Use `TeX_from_expression` when the input is a mathematical expression rather
than literal prose or trusted TeX source. The native mathematical modules handle
parsing, simplification and presentation automatically. Fractions, powers,
function names and grouping require no separate parser configuration.
The input is borrowed; free the returned object with `TeX_free`.

Algebra-only input deliberately includes native simplification, so it is not a
verbatim transcription of the source. It inherits the expression module's
domain conventions. Calculus operations are retained for typesetting instead
of being evaluated. It does not solve arbitrary equations or infer tensor semantics.
Malformed expressions return null and use the expression parser's diagnostics.
Null input and embedded NUL characters are rejected.

In the example below, `1/2(...)` means `(1/2) * (...)`. Write parentheses
explicitly when the whole product belongs in the denominator. MARS uses `log`
for base ten (rendered as `lg`); use `ln` for the natural logarithm.

```c
/**
 * @file TeX_expression_example.c
 * @brief Render ordinary mathematical text without writing TeX commands.
 *
 * Delegates parsing and readable arrangement to the native expression module,
 * prints the resulting TeX and releases both independently owned objects.
 */
#include <stdio.h>
#include <stdlib.h>

#include "TeX-t.h"

int main(void)
{
    string_t *input = string_new_with("1/2(x^2 - 4)/(x-1)*sin(x)/x*log(1/x)");
    TeX_t *notation = TeX_from_expression(input);
    string_free(input);
    int status = EXIT_FAILURE;
    if (notation)
        status = puts(TeX_source(notation)) == EOF ? EXIT_FAILURE : EXIT_SUCCESS;
    TeX_free(notation);
    if (status != EXIT_SUCCESS)
        fputs("Could not parse or print the expression.\n", stderr);
    return status;
}
```

```text
\frac{\left(x^{2} - 4\right)\mkern-2mu \sin(x)\mkern-2mu \lg(\frac{1}{x})}{2\mkern-2mu x\mkern-2mu \left(x - 1\right)}
```

## Native calculus shorthand

`TeX_from_expression` retains calculus notation instead of calculating it.
Use a parenthesised operand after a derivative prefix. The native parser accepts
`d/dx(...)`, `d^2/dx^2(...)` and `d^2/dxy(...)` alongside `Dx(...)`, `Dxy(...)`,
`Dxyx(...)` and `D[x^2y](...)`. Numerator and denominator derivative orders must
agree and must be positive integers. Mixed derivative variables retain their
application order; the operator denominator is written in reverse order, as
in composition of differential operators. These coordinate derivatives use
partial-derivative notation, including when only one coordinate is specified.

`@F` and `@Finv` retain forward and inverse Fourier transforms; `@L` and `@Linv`
retain Laplace transforms. `@S` retains an integral sign, with optional bounds,
`@Z` retains its sum and limits, and `@P` retains its product even when the result
could be computed. All registered MARS function names and aliases use the native
parser and its existing TeX renderings, including special functions and probability
distributions. There is no separate function allowlist in TeX. Use the expression
module's documented spellings and argument conventions. Algebra-only input still
uses the native beautifier. For evaluation, use the expression module's ordinary
parser and simplifier instead. No calculus grammar is duplicated in TeX.

The same conversion list includes inequalities, exact and approximate equalities,
congruence and a chained inequality. These are typeset without testing their truth.

## Converting native expression output

Pass the `string_t` returned by `expr_to_text(expression, style_EXPRESSION)`
directly to `TeX_from_expression`. The same native parser accepts braces,
variable and constant bindings, array bindings, Unicode operators, indexed
identifiers, registered functions and domain conditions. The rendered result
contains the symbolic body and its conditions, not the binding declarations;
bound values are not substituted into ordinary algebra.

This is useful when converting mathematical text produced by MARS, for example
after loading a saved expression. The programme below prints that native text,
then the TeX commands for a fraction containing a square root. The rendered
formula appears below the output. Its input bindings are `x = 2` and `c = 4`;
the typeset formula keeps the symbols `x` and `c`.

For an expression already in memory, requesting `expr_to_text(expression, style_LATEX)`
produces TeX directly. The round trip below demonstrates compatibility with the
native text format.

This is a conversion of the emitted mathematics, not recovery of its history.
If the expression renderer has already evaluated a Fourier transform, the TeX
adapter renders that result. Pass the original transform request to retain its
operator notation, as in the runnable calculus example above.

```c
/**
 * @file TeX_expression_style_example.c
 * @brief Convert native formula text into independently owned TeX notation.
 *
 * Native text retains the variable and constant bindings. TeX renders the
 * symbolic fraction and square root, keeping x and c as mathematical symbols.
 */
#include <stdio.h>
#include <stdlib.h>

#include "expression-t.h"
#include "TeX-t.h"

int main(void)
{
    expr_t *expression = expr_from_string("{sqrt(x^2+c)/(x+1) | x=2; c=4}", NULL);
    string_t *source = expression ? expr_to_text(expression, style_EXPRESSION) : NULL;
    TeX_t *notation = source ? TeX_from_expression(source) : NULL;
    int status = EXIT_FAILURE;
    if (source && notation && printf("Native text: %s\nTeX source: %s\n",
                                    string_c_str(source), TeX_source(notation)) >= 0)
        status = EXIT_SUCCESS;
    TeX_free(notation);
    string_free(source);
    expr_free(expression);
    if (status != EXIT_SUCCESS)
        fputs("Could not convert native expression output.\n", stderr);
    return status;
}
```

Output:

```text
Native text: { √(x² + c)/(x + 1) | x = 2; c = 4 }
TeX source: \frac{\sqrt{x^{2} + c}}{x + 1}
```

Rendered mathematics:

$$
\frac{\sqrt{x^{2} + c}}{x + 1}
$$

## Text-based alternatives to structured composition

The following complete programme repeats the root, indexed expression and
projection matrix examples using complete mathematical strings.
It also renders the one-dimensional Schrödinger equation from a single string.
Here `h` denotes the reduced Planck constant, `psi` depends on
`x` and `t`, and `V` is the scalar potential. Their arguments are suppressed
in the displayed equation. The native derivative syntax retains differentiation.

The same examples now use an array of native mathematical strings and one loop
calling `TeX_from_expression`. Symbolic indices use `r_n` or `r_(n+1)`;
this is scalar indexing, not tensor syntax. Whole equations retain their two
sides, and explicit scalar–matrix products retain the matrix layout. Undeclared
function calls on equation sides, such as `P(x)`, remain symbolic; write `P*x`
when multiplication is intended. Captions remain separate literal text.

Mathematical interpretation belongs to the native modules. The equation adapter
asks an operand-reader callback to interpret each side, and TeX supplies the
composition facilities. The algebraic beautifier may reorder equivalent terms.
Tensor syntax remains deferred.

```c
/**
 * @file TeX_text_alternatives_example.c
 * @brief Render native mathematical strings with one convenience call per formula.
 *
 * Native parsers interpret indices, equations, scalar–matrix products and calculus.
 * Captions remain separate literal text. Here h denotes the reduced Planck constant.
 */
#include <stdio.h>
#include <stdlib.h>

#include "TeX-t.h"

int main(void)
{
    const char *formulae[] = {
        "sqrt(x/2)",
        "r_(n) = root(1+x_(n)^2,3)/sqrt(1+@lambda^2)",
        "P(x) = 1/(1+x^2)*(1,x;x,x^2)",
        "i*h*Dt(@psi) = -h^2/(2*m)*Dxx(@psi)+V*@psi"
    };
    const char *captions[] = {NULL, "scaled & normalised", NULL, NULL};
    for (size_t i = 0; i < sizeof formulae / sizeof *formulae; ++i) {
        string_t *input = string_new_with(formulae[i]);

        string_free(input);

        if (!ok) {
            fputs("Could not render mathematical text.\n", stderr);
            return EXIT_FAILURE;
        }
    }
    return EXIT_SUCCESS;
}
```

## Native constants and infinity

and symbol bindings follow the expression parser's rules; a Greek symbol alone
is not a new numerical-constant definition. Euler's number and the imaginary

## Matrix literals and symbolic powers

`TeX_from_expression` also accepts `(1, 2; 3, 4)^x`. The literal must contain
an explicit column comma or row semicolon so it is distinguishable from scalar
parentheses. Matrix entries are parsed by `mat_from_text_expr`; the resulting
body uses the matrix module's square-bracket notation. A compound exponent must
be parenthesised, as in `(1, 2; 3, 4)^(x+1)`.

The power is displayed without evaluating the matrix operation: `^2` remains
a superscript rather than multiplying the matrix. Scalar entries retain the
native matrix parser's normal simplification. This convenience form accepts a
single literal with an optional scalar exponent and outer scalar bindings, not
general matrix arithmetic. Thus `(1, 2; 3, 4)^x+1` is rejected rather than
silently treating `x+1` as its exponent. Ordinary scalar parentheses retain their
existing meaning.

## Bound matrix powers and differential-equation problems

The same convenience API accepts outer bindings on a matrix literal or power.
Bindings are parsed by the native matrix and expression parsers, but symbolic
entries and exponents stay symbolic: `x = 3` does not replace the exponent `x`.
This also applies to a lone scalar expression such as `{ x | x = 3 }`.

Differential-equation inputs use the native parser and semantic presentation adapter.
The condition-only form below infers the independent variable `x` and treats the
residual as an equation equal to zero. Canonical `style_EXPRESSION` problem
strings with independent-variable, constant and condition sections are also
accepted. An ordinary equation entered with primes retains those primes, including
function-style initial conditions such as `y'(0)` and `y(0)`. Explicit coordinate
derivatives retain differential fractions and evaluation bars; partial derivatives
retain their coordinate labels. No solver is invoked. The
[prime construction example](#prime-notation-with-rpn) builds the same ODE with RPN operations.

```c
/**
 * @file TeX_bound_problems_example.c
 * @brief Render a bound matrix power and an ODE with initial conditions.
 *
 * Scalar bindings remain symbolic. Initial conditions are displayed explicitly,
 * without solving the differential equation or evaluating the matrix power.
 */
#include <stdio.h>
#include <stdlib.h>

#include "TeX-t.h"

int main(void)
{
    const char *sources[] = {
        "{ (1, 2; 3, 4)^x | x = 3 }",
        "{ y'' + 3y' + 40y | y'(0) = 1, y(0) = 0 }"
    };
    for (size_t i = 0; i < sizeof sources / sizeof *sources; ++i) {
        string_t *input = string_new_with(sources[i]);

        string_free(input);
        int printed = notation ? puts(TeX_source(notation)) : EOF;
        TeX_free(notation);
        if (printed == EOF) {
            fputs("Could not render the bound problem.\n", stderr);
            return EXIT_FAILURE;
        }
    }
    return EXIT_SUCCESS;
}
```

## Raw TeX syntax

`TeX_raw` accepts a complete mathematical expression written in TeX syntax.
The source may be authored directly or supplied by another renderer. It is copied
verbatim, without escaping, native expression parsing, simplification or evaluation.
`TeX_builder_finish` returns the resulting `TeX_t` in the usual way.

Raw source can also be an operand of later RPN operations. Its internal structure
is unknown, so arithmetic groups it conservatively to preserve its whole scope.
In the second example below, squaring applies to the entire sum.

Supply the mathematical body without `$...$`, `\(...\)` or `\[...\]` delimiters.
In a C string, each TeX backslash is written twice; text read from a file or text
box already contains ordinary single backslashes. Source is stored without syntax
validation; the TeX engine that typesets it reports invalid commands or grouping.

```c
/**
 * @file TeX_raw_source_example.c
 * @brief Preserve authored TeX syntax and combine it with reverse Polish construction.
 *
 * Raw input is copied verbatim. A subsequent stack operation groups the entire
 * raw operand without attempting to parse its TeX syntax or evaluate its value.
 */
#include <stdio.h>
#include <stdlib.h>

#include "TeX-t.h"

static int print_formula(TeX_builder_t *builder)
{
    TeX_t *notation = TeX_builder_finish(builder);
    int printed = notation ? puts(TeX_source(notation)) : EOF;
    TeX_free(notation);
    return printed == EOF ? EXIT_FAILURE : EXIT_SUCCESS;
}

int main(void)
{
    TeX_builder_t *b = TeX_builder_new();

    /* sqrt(x^2 + c)/(x + 1) */
    TeX_raw(b, "\\frac{\\sqrt{x^{2}+c}}{x+1}");
    int status = print_formula(b);

    /* (sin(x) + cos(x))^2 */
    TeX_raw(b, "\\sin x + \\cos x");
    TeX_integer(b, 2);
    TeX_pow(b);
    if (print_formula(b) != EXIT_SUCCESS)
        status = EXIT_FAILURE;

    TeX_builder_free(b);
    if (status != EXIT_SUCCESS)
        fputs("Could not construct raw TeX notation.\n", stderr);
    return status;
}
```

Output:

```text
\frac{\sqrt{x^{2}+c}}{x+1}
{\left( \sin x + \cos x \right)}^{2}
```

Rendered mathematics:

$$
\frac{\sqrt{x^{2}+c}}{x+1}
$$

$$
{\left( \sin x + \cos x \right)}^{2}
$$
